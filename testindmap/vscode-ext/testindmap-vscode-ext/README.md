# Testindmap - テスト仕様書マインドマップエディター

**Testindmap（テスト仕様書マインドマップ）** は、テストケースの設計・整理・管理をマインドマップ形式で視覚的に行えるVS Code拡張機能です。

テストケース間の依存関係や実行順序をノードと接続線で俯瞰しながら、各ノード内にMarkdownで前提条件・手順・期待結果をリッチに記述できます。

---

## 🌟 主な機能

- 🗺️ **ビジュアルマインドマップ操作**: ノードの自由配置、ドラッグ移動、4辺リサイズ、ノード間接続
- 📝 **MonoMD準拠のリッチMarkdown編集**: ダブルクリックで即時編集、チェックボックスやアラートブロック対応
- 🏷️ **テスト属性のクイック設定**: テストケースID、テスト種別（正常系/異常系/負荷/セキュリティなど）、ステータス（起票/実施中/パス/フェイル/保留）
- 🔄 **VS Code標準機能とのシームレス連動**: `Ctrl+S` での保存、`Ctrl+Z` / `Ctrl+Y` のUndo/Redo、未保存インジケータ（●）
- 📤 **柔軟なインポート・エクスポート**: TSV形式（Excel・スプレッドシート連携用）およびJSON形式での入出力
- 📴 **完全オフライン動作**: 外部CDNやネットワーク接続不要で、高セキュアな隔離環境でも軽快に動作

## 🚀 クイックスタート

### 1. マインドマップを開く
- **既存のファイルを開く**: `.testmap.json`, `.testindmap.json`, `.testmap.tsv` をエディタで開くと、自動的にマインドマップエディタが起動します。
- **通常のJSON/TSVファイルを開く**: ファイルを右クリックして「**次で開く... (Open With...)**」→「**Testindmap Editor**」を選択します。

### 2. 新規作成する
- コマンドパレット（`Ctrl+Shift+P`）を開き、`Testindmap: 新規テスト仕様書マインドマップを作成` を実行します。
- 保存先とファイル名を指定すると、新しいテスト仕様書エディタが開きます。

## 🎮 操作方法・ツールバーの徹底ガイド

### 上部ツールバー

| ボタン | 機能説明 |
| :--- | :--- |
| 🗑️ **すべてクリア** | キャンバス上のすべてのノードと接続線を一括削除します。誤操作防止のVS Code確認モーダルが表示され、実行後も `Ctrl+Z`（Undo）で元に戻せます。 |
| 📂 **インポート** | 外部のJSONファイルまたはTSVファイルを読み込み、マインドマップとして復元します。 |
| 💾 **エクスポート** | マインドマップを **TSV形式**（Excel貼り付け用）または **JSON形式** でワークスペースや任意の場所に保存します。 |
| ➕ **ノード追加** | キャンバス上に新しいテストケースノードを1つ追加します。 |
| 📝 **操作方法** | キャンバス操作やショートカットのクイックヘルプを表示します。 |

---

### キャンバス & ノードの基本操作

- **ノードの移動**: ノードの白い背景部分をドラッグして自由な位置へ移動できます。
- **ノードのリサイズ**: ノードの上下左右4辺にカーソルを合わせるとリサイズカーソルに変化し、ドラッグでサイズを自由に拡大縮小できます。
- **ノード同士の接続**:
  1. 接続元のノードにある上下左右の丸い「接続コネクター」をクリックします。
  2. 接続先のノードのコネクターをクリックすると、矢印付きの接続線が引かれます。
- **テストケースIDの変更**: ノード上部の `ID: TC-001` 部分をクリックすると直接編集できます。
- **種別・ステータスの変更**: ノード上部のプルダウンから「正常系 / 異常系」や「起票 / 実施中 / パス / フェイル / 保留」を選択できます。ステータスに応じてノードの枠線色が変化します。
- **右クリックメニュー**:
  - ノードを右クリック → 「🗑️ ノードを削除」
  - 接続線を右クリック → 「🗑️ 接続を削除」
- **キャンバスの全体移動（パン）**: 背景のグラデーション部分をドラッグすると、キャンバス全体を移動できます。
- **拡大・縮小（ズーム）**: `Ctrl + 上キー` でズームイン（拡大）、`Ctrl + 下キー` でズームアウト（縮小）、`Ctrl + 0` で100%等倍リセットが可能です。また、画面右下のズームコントローラー（`＋` / `−` / `100%`）や `Ctrl + マウスホイール` でも操作できます。

## ✍️ Markdown記述仕様（MonoMD 準拠ガイド）

本拡張機能のマークダウンプレビューは、各記号が明確で重複のない一意の役割を持つ **[MonoMD](https://github.com/KagenoMoheji/llm_challenge/tree/main/monomd)** レンダラに準拠しています。

テスト仕様書の記述に役立つ記法と記述例を以下に紹介します。

### 1. 基本書式

| 記述 | プレビュー結果 | 補足 |
| :--- | :--- | :--- |
| `**太字テキスト**` | **太字テキスト** | 重要項目や強調 |
| `__下線テキスト__` | <u>下線テキスト</u> | **下線（アンダーライン）** として機能（※イタリックではありません） |
| `~~取り消し線~~` | ~~取り消し線~~ | 廃止された手順など |
| `` `input_value` `` | `input_value` | パラメータ名や入力値 |

> 💡 **改行の仕様**: 空行を入れると自動的に `<br>`（改行）として処理されます。末尾に半角スペースを2つ入れる必要はありません。

---

### 2. リストとチェックボックス

テストの実行結果やチェックリストの作成に便利です。

```markdown
### テスト確認リスト
- [ ] 1. 入力バリデーションが通ること
- [ ] 2. 登録完了ダイアログが出ること
- [x] 3. DBにレコードが1件追加されること（確認済）

### 箇条書き
- 項目1
- 項目2
  - サブ項目
```

---

### 3. 情報・警告ブロック（コールアウト）

前提条件や注意すべき副作用を分かりやすく強調できます。

```markdown
:::info
【前提条件】
管理ユーザーとして事前にログイン済みであること
:::

:::warn
【注意】
テスト実行前にテスト用データベースのバックアップを取得してください
:::

:::alert
【既知の不具合】
Safariブラウザでのみボタンがはみ出るバグが起票されています
:::
```

---

### 4. 実行コードと期待結果ブロック

APIテストやCLIコマンドのテストに最適です。`:::output` を使うことで、実行コマンドと期待される出力結果を1つのブロック内に記述できます。

````markdown
```bash
curl -X POST https://api.example.com/v1/auth -d '{"user":"admin"}'
:::output
{"status": 200, "token": "abc123xyz"}
:::
```
````

---

### 5. テーブル（キャプション付き）

テスト入力値と期待値のマトリクス表を作成できます。テーブルの1行目に `[キャプション名]` を付与できます。

```markdown
| 入力ID | 入力パスワード | 期待結果 |[認証マトリクス]
|:---|:---|:---|
| admin | pass1234 | ログイン成功 |
| guest | wrongpass | エラーメッセージ表示 |
| (空文字) | pass1234 | 入力必須バリデーション |
```

### 📋 テストケースノードの記述例（テンプレート）

ノードのマークダウン部分をダブルクリックし、以下のテンプレートを貼り付けてご活用ください：

````markdown
# ユーザー新規登録テスト

:::info
**前提条件**:
- メール送信サーバー（Mock）が起動していること
- テスト用ブラウザで新規登録画面を開いていること
:::

## 📝 テスト手順
1. `ユーザー名` に「テスト太郎」と入力
2. `メールアドレス` に有効なアドレスを入力
3. `登録ボタン` をクリック

## ✅ 期待結果
- [ ] 登録完了画面に遷移すること
- [ ] 確認メールが1通送信されること
- [ ] データベースの `users` テーブルに登録されていること

| フィールド | 入力値 | 期待されるバリデーション |[入力データ]
|:---|:---|:---|
| name | テスト太郎 | 正常 |
| age | -1 | 「0以上の数値を入力してください」 |
````

## 💾 保存とファイル形式について

1. **自動同期**: ノードの移動やテキスト編集を完了（外側クリック）すると、VS Codeのテキストドキュメントへ自動反映されます。
2. **保存**: VS Codeの標準ショートカット `Ctrl+S`（Macは `Cmd+S`）でファイルに書き込まれます。
3. **データ構造**:
   - **JSON形式**: ノードの座標、サイズ、Markdownテキスト、ノード同士の接続情報（方向情報含む）が完全に保持されます。仕様書の原本保存に推奨されます。
   - **TSV形式**: タブ区切りの表形式データです。ExcelやGoogleスプレッドシートにそのままコピー＆ペーストして一覧化・報告用シートに変換できます。
